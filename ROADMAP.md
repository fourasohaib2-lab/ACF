# ACF Roadmap

## Current State (verified 2 September 2026)
- Core scientific foundation (thermodynamics, mathematics, model4d, encyclopedia) is implemented and compiles cleanly across all 1,345 `src/acf` Python files.
- Test suite, run in this repo's own dev environment: **2895 passed / 0 failed / 0 uncollectable**, stable across repeated runs. `ruff check` and `mypy src` both clean. See `docs/ACF_PHYSICS_GUARD_AUDIT_CHANGELOG.md` for the full history of what was audited and fixed to get here (fabricated-data removal, honest-disclosure conventions, real HPC/web/AI wiring).
- The ACF Complexity Engine (`src/acf/awci/`) is real and fully built out: Physical/Forecast Complexity split, real ensemble spread, real multi-model disagreement (AROME/ALADIN/ARPEGE), 2D/3D/4D fields (`spatial_field.py`/`vertical_field.py`/`temporal_field.py`), and every AWCI dashboard panel wired to one real `CoupledEarthSolver` computation per "Real Physics" click — see `docs/ACF_ARCHITECTURE_TARGET_GAP_MAP.md` for the full build log and honestly-documented limitations (native model levels only, no per-point forecast data in the fields).
- NWP workflow engines for AROME, ALADIN, ARPEGE, and SURFEX exist as adapters/ingestion code; full operational orchestration (multi-cluster failover, live assimilation feeds) is not yet in place.
- ESOC GUI and AWCI dashboard exist and run; broader real-time HPC/data-assimilation/satellite/radar integration described in `docs/ACF_Vision_1.0.md` is still largely aspirational — see the project's own module-maturity classification (LEVEL 0 absent → LEVEL 4 operationally integrated) before treating any module as "done."

Earlier versions of this file (superseded, see git history) stated "1,922 passed / 12 failed / 45 uncollectable" (August 2026) and, before that, "Version 1.0.0-LTS (Current)" with "100% passing coverage across 2,100+ tests" and "GESOP v1.0 CERTIFIED" — claims that did not specify an environment or link to a reproducible run, and could not be reproduced as stated. Treat any completion claim in this repository's `docs/` "certificate"/"sprint report" files as aspirational until it is backed by a run someone can repeat (see "Near-Term Priorities" below).

## Near-Term Priorities
- Declare `paramiko` in `requirements.txt` (used directly by `hpc_connector/ssh_connector.py` but previously undeclared) — done.
- Guard optional-dependency imports (`GRIBReader`, `NetCDFReader`) in `acf.importers/__init__.py` so a missing `xarray`/`cfgrib` install doesn't break unrelated imports — done.
- Split `pyproject.toml` dependencies into a lean "core" set and clearly-marked optional extras — **done, 2026-09-02**. `dependencies` is now `numpy`, `scipy`, `PyYAML` only; everything else moved to `[project.optional-dependencies]` (`gui`, `geospatial`, `formats`, `science`, `hpc`, `web`, `ai`, plus an `all` convenience extra and `dev`). Verified for real, not assumed: installed only the lean core into a fresh venv and import-smoke-tested every `acf` submodule — 51/57 import cleanly with zero extras; the other 6 (`gui`, `maps`, `data`, `hpc_connector`, `hpc_workflow`, `surfex`) fail exactly on the package their matching extra installs, confirmed by then installing `[hpc]` alone and re-testing. Two real bugs found this way, not by inspection: `pandas`/`shapely`/`rasterio`/`h5py` were declared dependencies matched by zero import anywhere in `src/` or `tests/` (removed, not moved to an extra); `PyYAML` was used directly by `core/config.py` but declared nowhere at all, only working in this dev environment because something else pulled it in transitively. Also documented (not fixed - a separate refactor): `acf.surfex`/`acf.hpc_workflow` import `HPCConnectionManager` at module level, so land-surface physics code requires `paramiko` just to import.
- Reconcile the ~150 auto-generated "certificate"/"sprint report" documents under `docs/` with the actual verified state, or clearly relabel them as historical/aspirational artifacts rather than current status — **done, 2026-09-02 (relabeled, not individually rewritten)**. Rewriting each of ~150 documents' specific claims individually wasn't practical in one pass; instead, every document whose filename matches a completion-claim pattern (`*_REPORT.md`, `*_CERTIFICATE.md`, `*_CERTIFICATION.md`, `*_AUDIT.md`, `*_ASSESSMENT.md`, `*_STATUS.md`, `*_READINESS.md`, `*_SCORECARD.md`, `*_CHECKLIST.md`, `*_DASHBOARD.md`, `*_LOG.md`, `*_MATRIX.md`, `*_NOTES.md`, bare `ACF_SPRINT_NNN.md`/`ACF_SPRINT_FINAL.md`, per-version `ACF_v0.X_CHANGELOG.md`, plus two version-suffixed audits missed by pure suffix matching) got a standardized, clearly-marked banner prepended (original content preserved unchanged below it) pointing to this file and `README.md`'s real, reproducible numbers. 140 of ~223 top-level `docs/*.md` files tagged this way; the other ~85 (specifications, governance/policy docs, risk registers, guides, roadmaps, this changelog) were left untouched — they're forward-looking or process documents, not completion claims, so a "may be aspirational" banner would misrepresent what they are.
